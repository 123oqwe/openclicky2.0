## 三、标准强调的"放到 GitHub 由工具执行"

| 需要落实 | 载体 | 现状 |
|---|---|---|
| 工作包/任务/负责人 | Issues + 标签 | 模板已建；标签待建 |
| 任务依赖 | Issue body `Depends on #N` | 模板字段已定，未在真实 issue 使用 |
| PR 目的/依赖/证据 | `.github/PULL_REQUEST_TEMPLATE.md` | 已建（PR #1 使用） |
| 模块所有权 | `.github/CODEOWNERS` | 已建 |
| 合并检查 | 必需 checks | **未配置**（需仓库设置 + 首个 CI） |
| 发布限制 | tag + Release | 未配置 |
| 验收结果 | `docs/06-acceptance.md` | 待第 6 步创建 |

## 四、残余风险

| 风险 | 影响 | 关闭条件 |
|---|---|---|
| 分支保护与必需检查未在 GitHub 启用 | "不能直推 main"目前靠本地 hook，不是强制 | 第 6 步配置 ruleset |
| 单人项目下"评审"可能退化为自评 | 独立性不足 | 引入 reviewer 子代理（已可用）并保留评审记录 |
| 标签/WIP 看板未落地 | 状态统计靠文档 | 第 6 步建 labels + Project |

## 五、结论

**PASS WITH RISK。** 规范本身覆盖 20 项且可执行；未完成的是"工具层强制"，属于第 6 步的交付物，已在风险表登记，不能据此宣称"规则已落实"。
