## 一、12 项字段逐份核对

## 二、标准里的 9 条检查问题

| 检查问题（标准原文） | 结果 | 证据 |
|---|---|---|
| 是否只有一个明确的核心决定？ | 基本满足 | 0001 含"技术栈 + crate 拆分"，0009 含"密钥 + 删除顺序"——两处可再拆，已在下方风险登记 |
| 是否解释当时的背景与约束？ | ✅ | 每份 §03 列出约束与假设，并标证据强度 |
| 是否比较现实可行的替代方案？ | ✅ | 每份 §05 至少 2 个真实候选（非稻草人） |
| 是否给出决定性理由？ | ✅ | §08 明确"不是因为它普遍更好，而是因为……" |
| 是否诚实区分事实/假设/未知？ | ✅ | §06 标"强/中/弱"，§03 列未验证项 |
| 是否记录代价与剩余风险？ | ✅ | §09 含负面后果、中性变化、剩余风险 |
| 是否能指导实现与检查？ | ✅ | §10 约束 + 落实确认（符合决策 / 达到预期） |
| 是否能判断何时重审？ | ✅ | §11 触发条件 + 可逆性 + 退出路径 |
| 是否保留审批与替代关系？ | ✅ | 决策者、状态、关联、历史；README 规定替代须新增记录 |

## 三、生命周期与可发现性

- 状态用语：`Accepted`；实施状态独立一行（全部为"未实现"），避免把"决定"当"已实现"。
- 索引：`docs/adr/README.md` 给出编号/标题/状态表 + 审查约定（一份一个决定、决策与实施分离、诚实三分类、替代不改历史、冲突按范围裁决）。
- 引用方式：tech-prd/SDD/TDS 均以编号引用；代码注释将引用 ADR 编号。

| 偏差 | 影响 | 处理 |

## 五、结论

**PASS WITH RISK。** 13 份 ADR 均满足"后来的人能看懂：当时为什么这样选、现在必须遵守什么、主动接受了什么代价、什么证据足以换一种做法"。

风险：全部决策证据仍是文档级；需要在真机冒烟后回填"达到预期"的判断（ADR 的 §10 已区分两类确认）。
