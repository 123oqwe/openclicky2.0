## 二、标准的 10 条判断

| 问题 | 结果 | 说明 |
|---|---|---|
| 测试范围清楚 | ✅ | 三平台/模块/非目标明确 |
| 需求与风险有对应检查 | ✅ | §02 矩阵 |
| 预期有独立依据 | ✅ | A-06 禁止用被测实现生成预期 |
| 别人能执行 | ✅ | 命令、初始化、清理、数据位置齐备 |
| 正常/异常/并发都考虑 | ✅ | 故障注入 + 并发用例 |
| 环境真实性说清 | ✅ | §09 保真度与局限 |
| 证据可复核 | ✅ | 绑定 commit + 输出摘要 |
| 未测项与失败公开 | ✅ | 五状态 + 分母 + 例外记录 |
| 验收与发布有明确条件 | ✅ | §19 + 阻断规则 |
| 变更后重新验证 | ✅ | §20 影响分析 |

## 三、残余风险

| 风险 | 影响 | 关闭 |
|---|---|---|
| 用例目前是"规格"，尚未全部写成代码 | 无执行证据 | 第 6 步按用例 ID 落地 |
| 假 provider 与真实端点有偏差 | 协议层漏检 | 样本对齐官方格式 + `doctor --online` |
| Agent 评测只有脚本化场景 | 真实模型质量未评 | 标记为"未覆盖"，不作为能力声明 |

## 四、结论

**PASS WITH RISK。** 规格已能指导"实现前就知道怎样判定对错"；第 6 步必须逐条产出可执行测试与证据，未落地的用例在报告中计为"未执行"，不得写成"通过"。
