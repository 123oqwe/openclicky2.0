## 二、标准的 10 条判断

| 问题 | 结论 | 说明 |
|---|---|---|
| 要求是否落到设计？ | ✅ | 22 项每项有对应单元与状态规则 |
| 模块能否独立实现并正确集成？ | ✅ | 端口签名 + 成功含义 + 失败分类写死 |
| 数据是否有明确约束？ | ✅ | DDL + 字典 + epoch |
| 动态行为是否完整？ | ✅ | 流程含失败/取消/恢复 |
| 安全是否落到执行点？ | ✅ | SEC 表 |
| 失败是否有明确去向？ | ✅ | 错误码 + 可重试标志 |
| 设计是否可被验证？ | ✅ | A-21 四类钩子 |
| 升级是否保护现有工作？ | ✅ | A-20 + 在途任务 |
| 实现是否仍有合理自由？ | ✅ | 只约束跨模块契约 |
| 文档是否与当前设计一致？ | ✅ | 状态分离 + 变更记录 |

## 三、残余风险

| 风险 | 影响 | 关闭 |
|---|---|---|
| `xcap` scale 未实测 | 指的位置偏移 | 第 6 步 `selftest --calibrate` |
| Wayland 注入不可用 | 听写/带做降级 | 运行时检测 + 文档 |
| 假实现保真度 | 协议层偏差 | 样本取自官方格式 + `doctor --online` |

## 四、结论

**PASS WITH RISK。** SDD 已能把"要做什么"落到"具体由哪个单元、用什么状态规则、失败时做什么、怎么验证"；不具备的是真机证据。
