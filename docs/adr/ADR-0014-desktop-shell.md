## 02 决策问题与范围边界

用什么承载"常驻 + 透明覆盖 + 全局热键"的桌面壳，热键如何绑定？**不涉及**：具体 UI 设计、安装器签名、自动更新（另属 ADR-0011/发布流程）。

## 03 背景、约束、假设与证据

- 产品要求"按住说话 + 在真实屏幕上画"（SRC-PRD B1/D1），核心已由 `crates/core` 实现并通过 135 个测试。
- 约束 C-1（三平台同代码基）、C-7（体积/内存）仍然成立。
- 事实：Tauri 2 提供透明/穿透窗口与全局热键插件；本机实测 `tauri build --bundles app` 产出 6.95 MiB 的 `.app`。
- 未验证：Windows/Linux 的打包与热键行为（release job 已写，尚未运行）。

## 04 决策驱动因素（按优先级）

1. 复用 Rust 核心，不重写业务（门槛）
2. 透明覆盖 + 多屏 + 全局热键可达（门槛）
3. 体积与内存（目标 ≤120MB / ≤220MB）
4. 不打乱单维护者节奏

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. Tauri 2 + 静态前端 | 现有选择 |
| B. Electron | JS 全栈，体积大 |
| C. 原生三份（Swift/WPF/Qt） | 体验最好，成本最高 |
| D. 无壳，仅 CLI | 最轻，但不满足"屏幕上画" |

热键子决策：

| 方案 | 说明 |
|---|---|
| H1. `tauri-plugin-global-shortcut` + Ctrl+Alt+Space | 现选择：插件要求非修饰键 |
| H2. 自建 CGEventTap / 低级钩子，支持"纯修饰键长按" | 更贴近 PRD 的 Ctrl+Opt，但要写三套钩子 |

## 06 方案比较与证据强度

| 维度 | A | B | C | D |
|---|---|---|---|---|
| 复用核心 | 强 | 中（FFI/子进程） | 弱 | 强 |
| 覆盖/穿透 | 强（已实测 macOS） | 强 | 强 | 无 |
| 体积 | 强（7MB 包） | 弱（~120MB） | 强 | 强 |
| 成本 | 中 | 中 | 高 | 低 |

证据强度：A 的 macOS 路径 **强**（本机产物）；Windows/Linux **弱**（未运行）。H1 **强**（插件文档 + 本机注册成功）；H2 **中**（未实测）。

## 07 决策结论

采用 **A + H1**：

- `apps/desktop` 为 Tauri 2 壳；两个窗口：`main`（900×640）与 `overlay`（透明、置顶、`ignore_cursor_events`）。
- 全局热键 **Ctrl+Alt+Space**：按下开始录音并以 30Hz 采样光标；松开提交轨迹给核心。
- 前端为静态 HTML/TS（`apps/desktop/ui/dist`），通过 Tauri IPC 调命令；不引入打包器。
- 覆盖层只负责把 `PointerPlan` 画成 Canvas 笔迹；不解析注解文本。

## 08 选择理由与关键取舍

理由：核心已经是 Rust，壳只是"窗口 + 热键 + 画布"；Tauri 用系统 WebView，包体 7MB，符合 C-7。

取舍：**热键从"按住 Ctrl+Opt"退化为"Ctrl+Alt+Space"**（插件限制），与 SRC-PRD 有可见差异；H2 能在后续补上，但需要三套平台钩子，先不做。放弃 Electron 的生态与原生三份的极致体验，换取单代码基与体积。

## 09 后果与剩余风险

中性变化：热键改成带空格键的组合，文档与引导必须一致（`05-deployment.md` 已写）。

正面：7MB 包、复用核心、覆盖层可独立演进。

负面：WebView 渲染差异（Linux WebKitGTK）；H1 无法表达"纯修饰键长按"。

剩余风险：Windows/Linux 打包与热键未验证；覆盖层在多屏与缩放下的坐标需真机校准。

## 10 实施约束与落实确认

- 壳内不得出现业务规则；只能调 `crates/core` 的公开 API。
- `overlay` 必须 `set_ignore_cursor_events(true)`，否则会挡住用户操作。
- 单实例由 `platform::singleton` 保证（壳启动即取锁）。
- 落实确认分两类：**符合决策**（壳只装配、热键路径正确）与**达到预期**（真机上按住说话可用）。前者已由代码结构保证，后者仅 macOS 冒烟过。

## 11 重新审视条件、可逆性与退出路径

重审：若 Windows/Linux 的热键或覆盖层不可用；或用户明确要求"纯修饰键长按"；或 WebView 在目标机器上不可用。

可逆性：高。壳可替换为原生三份，`crates/core` 不动；H1→H2 只改热键注册层。

退出路径：保留 CLI（`apps/cli`）作为无 GUI 入口，任何时刻可交付。
