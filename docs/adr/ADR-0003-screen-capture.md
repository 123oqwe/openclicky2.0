# ADR-0003 捕获入口收敛为唯一门禁，只在按键瞬间采集屏幕

| 字段 | 内容 |

| 决策者 | 人类维护者（本项目唯一有权接受者） |
| 实施状态 | 实现中（采集与坐标已实现；`capture_all(&guard)` 的类型化门禁待 F3）（详见 `06-acceptance.md`） |

## 02 决策问题与范围边界

怎样在三个平台取得多显示器截图，并**从架构上保证**"不按键就不看屏幕"？边界：不涉及画什么（前端），不涉及 OCR。

## 03 背景、约束、假设与证据

- C-4：只在按键那一刻采集（信任底线，也是最大差异化）。
- 需支持多显示器、Retina/HiDPI 缩放、鼠标所在屏标记。
- 假设 H-1：`xcap` 可取原始分辨率并枚举显示器（未实测）。
- 证据：原作开源版证明"按键→多屏截图→降采样"可行（SRC-RESEARCH §8.1）。

## 04 决策驱动因素

1. 隐私可证明（可审计的单一入口）
2. 三平台一致
3. 延迟（≤250ms）
4. 坐标可换算（指的确准）

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. `xcap` + `CaptureGate` 单入口 + 抽象 trait | 三平台一库 |
| B. 平台原生 API 直调（CGDisplayStream / DXGI / XShm） | 各自实现 |
| C. 持续帧缓冲（录屏式），按键时取最后一帧 | 延迟最低 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 隐私合规（不按键不看） | 强 | 强 | **弱**（持续采集） |
| 延迟 | 中 | 强 | 强 |
| 实现成本 | 低 | 高（3×） | 中 |
| 平台一致性 | 强 | 弱 | 弱 |

证据强度：A **中**，B **中**，C **强（明确违反 C-4，直接排除）**。

## 07 决策结论

采用 **A**。

- `core::privacy::CaptureGate`：唯一允许触发采集的类型；构造需 `CaptureReason`（`Hotkey`/`UserRetry`/`OnboardingDemo`）。
- `ScreenSource` trait 在 `platform` 实现；`core` 内看不到平台 API。
- 采集策略：所有显示器各截一张；**发给模型的最多 3 张**（主屏原图 + 其余屏缩略，长边 1280，JPEG q=0.8）；原图只在本机用于绘制锚点，不随请求发出。
- 标记鼠标所在显示器索引；模型注解坐标限定在对应索引的图片像素空间。

## 08 理由与取舍

理由：把隐私变成类型系统约束（无 gate 无法采集），而不是"记得别采集"。

取舍：放弃 C 的零延迟；接受每次按键 100–250ms 的采集开销（与"松手后 2.5s 开口"预算相容）。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：可写测试断言"未开 gate 时 ScreenSource 调用次数 = 0"；审计日志可证明。

负面：连续追问时重复采集（可接受，PRD B11 要求"刚离开的页面也能回看"，实现为**内存中**保留上一帧 30 秒，不落盘）。

剩余风险：macOS 首次截图会触发 TCC 弹窗导致首帧丢失 → 引导里预热一次。

## 10 实施约束与落实确认

- `ScreenSource` 只允许被 `CaptureGate::capture()` 调用；CI 脚本检查无其它调用点。
- 测试用 `FakeScreen` 断言调用次数与 `reason`。
- 落实确认：INV-1 用例通过（10 分钟内不按键，采集计数为 0）。

落实确认分两类：**符合决策**（实现是否遵守本决定的约束）与**达到预期**（遵守之后是否真的改善了当初关注的问题）。前者通过不证明后者成立；若仅前者成立，应重新评估本决定而不是宣布成功。

## 11 重审条件、可逆性、退出路径

重审：H-1 失败；或需要"持续看屏"的新能力（则必须新 ADR 并重新评估信任）。

可逆性：高（trait 边界清晰）。退出路径：方案 B 按平台替换 `ScreenSource` 实现。
