## 02 决策问题与范围边界

后台任务如何被创建、执行、暂停、取消、恢复？工具权限在哪一层执行？边界：不实现"多个具名 agent 各有人格/头像"（SRC-PRD H21 的商业形态），也不实现跨设备迁移。

## 03 背景、约束、假设与证据

- 约束：模型不可信（可能幻觉、可被提示注入）→ 权限必须在模型外执行（OWASP 建议）。
- 需求：10 秒内取消不计费（H3）、20 分钟无响应自动停（H11）、断点续做（H9）、一次问一小组问题（H13）。
- 证据/假设：工具循环 + 检查点是业界标准做法；本项目需自己验证"恢复后不重复副作用"。

## 04 决策驱动因素

1. 安全（越权与破坏性操作）
2. 可恢复（长任务）
3. 成本可控
4. 可测（脚本化模型）

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 进程内单 Agent，任务为一等对象，工具策略层 | 自研循环 |
| B. 嵌入外部 agent 框架/二进制（如 Codex 类） | 打包子进程 |
| C. 多 Agent 编排（规划者+执行者+审查者） | 复杂 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 权限可控 | 强 | 弱（外部框架自己决定） | 中 |
| 可测性 | 强 | 弱 | 中 |
| 成本/复杂度 | 中 | 中（体积大） | 高 |
| 恢复 | 自研强 | 依赖框架 | 复杂 |

证据强度：A **中—强**（可控）；B **弱**（不可控权限）；C **弱**（过度设计）。

## 07 决策结论

采用 **A**：

- `Task`：`{id, name, goal, state, created_at, updated_at, checkpoint, units_charged, workspace}`。
- 状态：`Queued → Running ⇄ WaitingUser | WaitingApproval → Completed | CompletedUnverified | Failed | Paused | Canceled`。
- 循环：`build_context → chat(tools) → 若有 tool_call 则 policy.check → execute → 记录 → checkpoint`，步数上限 30。
- `Policy`（模型外）：
  - `Read` 自动；
  - `Write` 工作区内自动，工作区外需批准；
  - `Destructive`（删除/覆盖已存在重要文件/`shell`）每次批准，`Not now` 管 30 分钟；
  - `External`（`fetch_url`/`http_get_json`/发布类）自动但受 SSRF 与域名策略约束；上传本机文件到外部需批准。
- 副作用保护：工具结果写 `task_steps`；恢复时读"已发生动作"清单，禁止重放非幂等工具。
- 结束判定：必须有一个客观证据（文件 stat / HTTP 结果 / 用户确认），否则 `CompletedUnverified`。

## 08 理由与取舍

取舍：放弃"多具名 agent"的人格化卖点，换取权限清晰与可测；放弃外部 agent 二进制，换取体积与权限控制。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：每次工具调用可审计；测试可脚本化；恢复语义明确。

负面：能力弱于专用编码 agent（无仓库级上下文管理）；`shell` 工具风险高（默认关闭）。

剩余风险：模型可能反复尝试同一失败工具 → 同签名 2 次即放弃该路径。

## 10 实施约束与落实确认

- 工具实现必须返回结构化 `ToolOutcome`，禁止返回自然语言代替结果。
- `policy` 不得读取模型文本作为授权依据。
- 落实确认：`tests/e2e_agent.rs`（成功/取消/恢复/越权/假成功 5 条主路径）。

## 11 重审条件、可逆性、退出路径

重审：需要多 agent 协作、或需要仓库级编码能力（届时引外部 harness 并新写 ADR）。

可逆：中。退出：`agent` 循环可替换为外部 runner，任务模型保留。
