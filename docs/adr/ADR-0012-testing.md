## 02 决策问题与范围边界

在无模型密钥、三平台 CI、单人维护的条件下，怎样获得可信证据？边界：不替代真实设备冒烟与在线探测。

## 03 背景、约束、假设与证据

- C-5：必须离线、确定性。
- 真实 API 不可用（R-2）→ 云端路径只能靠协议级假实现覆盖。
- 经验：把外部世界全部收敛为 trait，是让"关键逻辑可测"的最短路径。

## 04 决策驱动因素

1. 确定性（无 flaky）
2. 覆盖关键行为（状态机、协议、策略、坐标、计费）
3. 三平台同一套
4. 运行快（< 60s）

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 端口注入 + 脚本化假实现 | 本项目 |
| B. `httpmock`/`wiremock` 起本地服务 | 真实 HTTP |
| C. 只做手动测试 | 无自动化 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 确定性 | 强 | 中（端口/并发） | 无 |
| 协议覆盖 | 中（需手写样本） | 强 | 无 |
| 速度 | 强 | 中 | — |
| 维护 | 强 | 中 | — |

证据强度：A **强**；B **中**；C 排除。

## 07 决策结论

采用 **A**，B 仅用于 SSE 与 multipart 的**一次性**协议校验（可选，不阻塞 CI）：

- `ScriptedTransport`：按 `(method, path)` 或请求序号返回预置响应/错误；可断言请求体（含图片是否随附、注解提示是否注入）。
- `FakeScreen/Audio/Transcriber/SpeechOut/Injector/Overlay/Clock/Store(tmp)`：内存实现，记录调用序列。
- 三层测试：单元（模块）→ 集成（`tests/e2e_*.rs` 驱动完整链路）→ 手工冒烟（真实进程，记录在 `06-acceptance.md`）。
- 覆盖率目标：`core` ≥ 80%（`cargo llvm-cov`，CI 仅 macOS 统计）。

## 08 理由与取舍

取舍：放弃"用真实 HTTP 打供应商"带来的协议保真度，换取离线与确定性；用样本文件锁定已知响应形态。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：每个 PR 都能跑完整逻辑；失败可复现。

负面：供应商真实行为变化不会被 CI 发现 → 由 `doctor --online` 与用户报告兜底。

剩余风险：假实现与真实偏离（缓解：样本来自官方文档示例格式）。

## 10 实施约束与落实确认

- 测试不得依赖网络、不得 `sleep` 真实时间（用 `TestClock`）。
- 落实确认：CI 三平台 `cargo test --workspace` 全绿。

落实确认分两类：**符合决策**（实现是否遵守本决定的约束）与**达到预期**（遵守之后是否真的改善了当初关注的问题）。前者通过不证明后者成立；若仅前者成立，应重新评估本决定而不是宣布成功。

## 11 重审条件、可逆性、退出路径

重审：获得测试用密钥；或 CI 允许网络时增加"契约探测"。

可逆：高。
