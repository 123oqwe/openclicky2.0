# ADR-0013 听写：增量重转写 + 最长公共前缀合并，追求"边说边出字"

## 02 决策问题与范围边界

如何在不引入流式语音模型的前提下，做到"说完就出字"（原作约 450ms）？边界：不训练模型、不做本地推理。

## 03 背景、约束、假设与证据

- 供应商 STT 多为"整段提交"（`/v1/audio/transcriptions`），本地端点亦然。
- 需求：F1 约 450ms 首字；F8 长录音不丢；F4 20 秒内纠错进词典。
- 假设：短音频（1–2s）转写延迟 < 800ms。

## 04 决策驱动因素

1. 感知延迟
2. 一致文本（不重复、不回退）
3. 兼容多端点
4. 可测（时间与音频都可注入）

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 边说边每 700ms 重转写全部音频，取最长公共前缀增量注入 | 增量 |
| B. 等松开后一次转写 | 简单，延迟高 |
| C. 接专用流式 STT（WebSocket） | 质量好，端点受限 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 首字延迟 | 强（~1s） | 弱（2–4s） | 强（<500ms） |
| 端点兼容 | 强 | 强 | 弱 |
| 成本 | 中（多次转写） | 低 | 中 |
| 实现复杂度 | 中 | 低 | 高 |

证据强度：A **中**；B **强（但达不到指标）**；C **中**。

## 07 决策结论

采用 **A**：

- 录音环形缓冲（16k PCM16）；每 700ms 提交"从上次已稳定点到当前"的窗口（≤ 8s），得到 `partial`。
- 合并：与上一次 `partial` 求最长公共前缀；仅注入新增后缀。稳定点 = 连续两次 partial 前缀一致的位置。
- 结束时做最后一次整段转写 → 与已注入文本做 diff：仅当差异位于末尾 20 秒内且是"纠错"（编辑距离小）时，回退并重写该段；否则忽略（保证不抖动）。
- 整理：一次轻量 LLM 调用（可关）修语法但不改写；保守规则（不插入破折号、不改写）。
- 词典：用户 20 秒内手改 → 记录 `heard → corrected` 对；后续转写前做上下文提示（STT `prompt` 参数）与后处理替换。
- 计量：每次听写 0.5u，不按重转写次数计。

## 08 理由与取舍

取舍：接受多次转写的成本（短音频便宜）与"末尾可能重写"的观感，换取端点无关与可测。

## 09 后果与剩余风险

正面：首字 ~1s；长录音安全；词典自适应。

负面：网络抖动时 partial 反复 → 用"稳定点"抑制；极短词（<300ms）可能漏。

剩余风险：某些端点不支持 `prompt` 参数 → 仅后处理替换。

## 10 实施约束与落实确认

- 合并逻辑必须是纯函数 `merge_partial(prev, next) -> (common, suffix)`，可单测。
- 落实确认：`tests/dictation_merge.rs`（前缀一致/纠正/回退/中文无空格/终端守卫）。

## 11 重审条件、可逆性、退出路径

重审：主流端点普遍提供 WebSocket 流式；或延迟指标不达标。

可逆：高（`Transcriber` trait 不变，替换策略即可）。
