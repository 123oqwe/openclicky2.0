## 02 决策问题与范围边界

一次性确定 12 个会阻塞施工的产品/工程选择：发什么、首跑怎么配、状态怎么显示、多屏承诺、任务由谁执行、预算怎么显示、账号与付费做不做、连接器/扩展/3D 如何处置、数据模型是否为多用户留位、数据库是否加密、语言范围、更新验签何时做。

不决定：具体 UI 视觉、模型供应商选择、定价（本版本无付费）。

## 03 背景、约束、假设与证据

- 三次独立审计（产品/UX、数据/安全、依赖/一致性）共 40+ 条发现，其中 6 条已用仓库证据复核：界面文件未入库、Release 不挂桌面产物、`TC-SEC-001/002` 编号撞车、附录 A 18/30 规格、05 产物矩阵过期、麦克风权限恒 true。
- 业主目标：完整还原 PRD 的核心体验，不阉割；同时要商业级稳定与安全。
- 约束：单维护者、无服务端、无结算主体（ADR-0002）；预算护栏替代计费（ADR-0010）。

## 04 决策驱动因素（按优先级）

1. 非技术用户能装、能配、能日常用（门槛）
2. 不烧钱、不被绕过（门槛）
3. 数据不成为"改不动的死穴"（门槛）
4. 与 PRD 的偏离必须可见、可解释
5. 单维护者可交付

## 05 候选方案

每条决策见 §07 表格的"选定 / 放弃"两列；被放弃的方案保留理由，便于将来重审。

## 06 方案比较与证据强度

| 决策 | 证据强度 |
|---|---|
| 桌面优先发布 | 强（本机 `.app` 已产出 6.95MiB 并运行 8s） |
| 首跑向导 | 强（现状无设置页，`NoApiKey` 即死路） |
| 主屏优先 + 明示 | 中（SDD 原写每屏一窗；成本未测） |
| 任务在桌面进程执行 | 强（现状桌面无 `create_task`，批准按钮无宿主） |
| 预算下沉到出站层 | 强（现状 `can_start` 仅 1 个调用点） |
| owner 列 | 强（迁移成本今天接近零） |
| 权限硬化而非加密 | 中（明文库对抗不了镜像/备份，已记为重审条件） |
| 不做账号/付费 | 强（无服务端与结算主体） |

## 07 决策结论（Q1–Q12 逐条）

| # | 决策 | 选定 | 放弃 | 理由 |
|---|---|---|---|---|
| Q1 | 本次发什么 | **B：桌面版最小 UI + 三平台安装包齐了再发**，CLI 保留为无 GUI 入口 | 只发 CLI | 目标是给不懂代码的人用 |
| Q2 | 首次填 key | **A：主窗口两步向导**（粘 key → 拉模型 → 选一个 → 保存） | 只靠终端/TOML | 现状"打开设置"指向不存在的页面 |
| Q3 | 状态显示载体 | **B：先用覆盖层画状态条 + 字幕 + 任务卡**，notch 放 v2.1 | 立即做 notch | 先能日常用，再追外观 |
| Q4 | 多显示器 | **B：主屏保证，第二屏明确提示"暂不支持指点"** | 每屏一窗 | 诚实降级，不装懂 |
| Q5 | 任务由谁执行 | **A：桌面进程自持 runner + 系统通知** | 命令行跑、桌面只看 | 否则批准按钮永远点不到 |
| Q6 | 预算显示 | **A：折成"约可问 N 次 / 约可办 N 件事"** | 只显示单位/百分比 | 用户看不懂等于没有 |
| Q7 | 账号与付费 | **A：本版本不做**，写入"不做清单"；PRD 的登录/套餐/团队版标注"本版本不实现" | 做后端/支付/合规 | 无服务端与结算主体 |
| Q8 | 连接应用/扩展/3D | **A+B：本期"延期"（不是删功能）；随后用 MCP 补连接能力** | Chrome 商店扩展、3D 引擎 | 成本与审核门槛 |
| Q9 | 多用户留位 | **A：现在就加 `owner` 列（默认 `'local'`）** | 永久单机假设 | 今天零成本，将来免大迁移 |
| Q10 | 数据库加密 | **A：先做目录 0700 / 文件 0600**；SQLCipher 记为"支持共用电脑时"的重审条件 | 立即 SQLCipher | 今天能做且够用 |
| Q11 | 界面语言 | **A：先中文 + 英文**；PRD 的 18 种标为"目标，分批交付" | 一次做 18 种 | 翻译与排版成本 |
| Q12 | 更新验签 | **A：要，但排在安装包之后**（v2.0.x） | 永不自更新 | 否则用户装的是死版本 |

## 08 选择理由与关键取舍

理由：把"业主能感知的价值"排在"工程完备性"之前——先让产品能装能配能用，再补数据与安全的结构性债务。

取舍：

- 放弃"立刻对齐 PRD 的 notch 与每屏指点"，换取 1–2 周内可交付；
- 放弃"一次做 18 语言与付费体系"，换取单维护者可完成；
- 接受"主屏优先"的体验折扣，但必须显式提示，不能假装支持。

## 09 后果与剩余风险

中性变化：文档需要一次性对齐（本文 + 05/06/SDD/TDS）；热键与 PRD 的差异必须在引导与文档中说明。

负面：v2.0 不是"完整 PRD"，是"可用的核心"；团队版/付费/扩展/3D 无归属，需在 v2.x 逐个立项。

剩余风险：三平台安装器未跑；更新验签未做；MCP 连接器仍是计划；数据库明文（已记为条件）。

## 10 实施约束与落实确认

- 任何阶段不得删减已承诺的功能，只能"延期并写明"（业主明确要求）。
- 每个阶段必须先写失败测试再改实现（playbook §10、TDS §19）。
- 阶段完成的判据是**业主能在自己机器上完成一条真实路径**，不是"测试变绿"。
- 落实确认分两类：**符合决策**（文档与实现按 §07 执行）与**达到预期**（业主真机走通）。

## 11 重新审视条件、可逆性与退出路径

重审：

- 业主决定做账号/付费（Q7 翻转）→ 需要后端与合规，本文全部相关决策重开；
- 多用户/共用电脑需求出现 → Q10 升级为 SQLCipher，Q9 的 `owner` 变成真隔离；
- 安装器在三平台任一失败 → Q1 回退为 CLI-first。

可逆性：Q3/Q4/Q8 可逆（体验层）；Q9/Q10 需要迁移（已按最小成本设计）。

退出路径：CLI 始终可用（`apps/cli`），桌面壳失败不影响核心能力。
