# ADR-0004 听写与起草采用"按键优先、剪贴板兜底"的注入阶梯

## 02 决策问题与范围边界

怎样把听写/起草的文字可靠地送进**当前聚焦的任意应用**，并在终端、密码框等危险上下文里不造成破坏？边界：不做无障碍树遍历（不读 UI 结构）。

## 03 背景、约束、假设与证据

- 目标应用五花八门（Electron、原生、终端、浏览器）。
- 硬性要求：终端里不得执行命令（F7）；密码/卡号不代填（SEC-7）；注入失败必须剪贴板兜底且**明确告知**（G3）。
- 假设 H-2：`enigo` 支持 Unicode 文本注入与按键（未实测）。
- 证据：剪贴板+粘贴是跨应用最稳的通用路径（Wispr Flow 等同类产品的公开做法）。

## 04 决策驱动因素

1. 不破坏用户数据（终端/密码）
2. 成功率
3. 保持用户原剪贴板
4. 三平台一致

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 直接合成按键（Unicode 逐字） | `enigo.text()` |
| B. 剪贴板写入 + 合成 Cmd/Ctrl+V + 还原剪贴板 | 通用 |
| C. 无障碍 API 写 AXValue | 仅 macOS/Cocoa |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 跨应用成功率 | 中（IME/终端差） | 强 | 弱（很多应用不实现） |
| 中文/表情 | 中 | 强 | 中 |
| 剪贴板污染 | 无 | 有（可还原） | 无 |
| 实现成本 | 低 | 中 | 高 |

证据强度：B **中—强**（业界通用）；A **中**；C **弱**。

## 07 决策结论

采用 **A→B 阶梯**：

1. 先尝试 `enigo.text()`（快、无副作用）。
2. 失败或目标为非原生输入（检出终端/浏览器常见类别）→ 剪贴板路径：保存原剪贴板（文本/图片）→ 写入 → 合成粘贴 → 200ms 后还原原剪贴板。
3. 两者都失败 → 保留文本在剪贴板 + 通知"已复制，请手动粘贴"。

**三重守卫**（在 `dictation::guards`，不依赖模型）：

| 守卫 | 规则 |
|---|---|
| G-TERM | 目标进程名命中终端集合（Terminal/iTerm2/WindowsTerminal/powershell/bash/zsh/alacritty/kitty/wezterm）→ 合并换行、剥离首尾空白、拒绝包含 `\n` 的多行；只注入单行 |
| G-SECRET | 文本命中敏感词（密码/验证码/卡号/cvv/password/otp）即拒绝注入并说明，**不判断"意图"**（意图不可靠）；保证边界：不覆盖用户手动输入，也不阻止用户自己粘贴 |
| G-NOFOCUS | 无聚焦可编辑元素（前台为本应用自身或桌面）→ 不注入，改为在聊天里显示 |

## 08 理由与取舍

取舍：接受剪贴板短暂被占用（200ms）与还原复杂度；放弃"零副作用"的纯按键路径作为唯一方案。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：中文/长文本可靠；终端安全；失败可见。

负面：剪贴板管理器可能记录（文档提示可关闭）；极少数应用禁用粘贴。

剩余风险：Wayland 下 XTest 注入无效 → 检测并提示切 X11 或用剪贴板手动粘贴。

## 10 实施约束与落实确认

- 注入前必须调用 `guards::check()`；返回 `Denied` 时禁止调用 `TextInjector`。
- 剪贴板还原必须在 `finally` 语义下执行（Drop guard）。
- 落实确认：`tests/dictation_terminal.rs`、`tests/inject_guards.rs` 通过。

落实确认分两类：**符合决策**（实现是否遵守本决定的约束）与**达到预期**（遵守之后是否真的改善了当初关注的问题）。前者通过不证明后者成立；若仅前者成立，应重新评估本决定而不是宣布成功。

## 11 重审条件、可逆性、退出路径

重审：H-2 失败；或需要富文本/图片注入。

可逆：高（trait 单一方法）。退出：新增平台实现（macOS CGEvent / Windows SendInput）。
