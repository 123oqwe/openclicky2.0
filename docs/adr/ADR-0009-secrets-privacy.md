## 02 决策问题与范围边界

密钥存哪、日志能写什么、删除要做到什么程度、权限撤销如何生效？边界：不做企业合规认证（SOC2 等），不做远程擦除。

## 03 背景、约束、假设与证据

- C-3：密钥不得进入仓库/日志/崩溃报告。
- S4：删除账号要删服务器数据、分析、本机 agent 文件，只保留邮箱/原因/用量/付款记录 → 本项目无服务器，等价为"删本机全部数据 + 保留最小审计"。
- 假设：`keyring` 在 Linux 无 secret-service 时失败（需降级）。

## 04 决策驱动因素

1. 密钥不泄漏
2. 删除可验证
3. 权限撤销即时生效
4. 跨平台可行

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 系统钥匙串（keyring）+ 内存 `SecretString` | 标准 |
| B. 本地加密文件（AES-GCM + 主密码） | 自主 |
| C. 明文配置（0600） | 最简 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 抗本机窃取 | 强 | 中 | 弱 |
| 用户体验 | 强（无主密码） | 中 | 强 |
| Linux 可用性 | 中（依赖桌面环境） | 强 | 强 |
| 实现成本 | 低 | 中 | 低 |

证据强度：A **强**；B **中**；C **强但明确不满足 C-3**。

## 07 决策结论

- **主路径 A**：`platform::secrets` 用 `keyring` 存取（service=`openclicky`，user=`provider/<id>`）。
- **降级**：keyring 不可用 → 使用 `secrets.enc`（AES-256-GCM，密钥由机器绑定信息派生）+ 首次提示"当前系统无钥匙串，已使用本地加密文件"。
- `SecretString`：`Debug`/`Display` 打码；禁止 `serde::Serialize`。
- 脱敏：`security::redact` 覆盖 `Authorization`、`x-api-key`、`sk-`、`Bearer`、32+ 位 hex/base64、`key=`。
- 日志：默认不写用户文本（`debug_allow_text=false`）。
- 删除：`deletion::plan()` 生成步骤清单 → 逐项执行 → 逐项报告成功/失败（S4"删除失败要明说"）。
- 权限撤销：每个工具调用前重新检查（macOS `AXIsProcessTrusted`、`CGPreflightScreenCaptureAccess`；Linux `DISPLAY`；Windows 无）。

## 08 理由与取舍

取舍：接受 Linux 降级路径的复杂度，换取"任何 Linux 桌面都能用"；放弃主密码方案（用户负担）。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：密钥不与配置同处；日志可安全分享用于排错。

负面：Linux 无桌面环境时降级方案安全性弱于钥匙串（已提示）。

剩余风险：内存中密钥可能被同用户进程读取（桌面应用无法完全避免）。

## 10 实施约束与落实确认

- 禁止 `println!` 出现在 `secrets`/`providers` 路径（CI grep 检查）。
- 落实确认：`tests/redact.rs`、`tests/deletion.rs`、`tests/capture_gate.rs`。

落实确认分两类：**符合决策**（实现是否遵守本决定的约束）与**达到预期**（遵守之后是否真的改善了当初关注的问题）。前者通过不证明后者成立；若仅前者成立，应重新评估本决定而不是宣布成功。

## 11 重审条件、可逆性、退出路径

重审：需要企业部署（集中管理密钥）；或 Linux 主密码需求上升。

可逆：高（`Secrets` trait）。退出：改为 B（加密文件 + 主密码）。
