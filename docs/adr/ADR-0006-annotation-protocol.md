## 02 决策问题与范围边界

模型怎样告诉应用"指这里/画这个"？边界：不涉及渲染像素风格实现（前端），不涉及 3D。

## 03 背景、约束、假设与证据

- 开源版证明极简协议可行：`[POINT:x,y:label:screenN]`，正则提取后换算（SRC-RESEARCH §8.1）。
- 需要扩展到多种图形、多步带做、锚点跟随滚动（D2/D4）。
- 约束：不能用 JSON mode 作为唯一路径（很多兼容端点不支持）；解析失败必须优雅降级。

## 04 决策驱动因素

1. 模型易产出（few-shot 即可）
2. 解析容错（大小写、空格、缺字段）
3. 可校验（越界/非法不得画出界）
4. 可扩展到带做与锚点

## 05 候选方案

| 方案 | 说明 |
|---|---|
| A. 行内标签语法（正则 + 结构解析） | 文本里嵌入 |
| B. 强制 JSON（response_format） | 结构化 |
| C. 工具调用（function calling）表达注解 | 结构化 |

## 06 方案比较与证据强度

| 维度 | A | B | C |
|---|---|---|---|
| 兼容端点覆盖 | 强 | 弱 | 中 |
| 流式可用 | 强（后处理） | 弱 | 中 |
| 误解析风险 | 中（可容错） | 低 | 低 |
| 实现成本 | 低 | 中 | 高 |

证据强度：A **强**（有开源先例 + 本项目会用测试锁定）；B/C **中**。

## 07 决策结论

采用 **A**，语法固定如下（`screenN` 可省，缺省为鼠标所在屏）：

```
[POINT:x,y:label:screenN]                 指（飞过去 + 标签）
[DRAW:screenN:circle(cx,cy,r)]
[DRAW:screenN:rect(x,y,w,h)]
[DRAW:screenN:arrow(x1,y1,x2,y2)]
[DRAW:screenN:line(x1,y1,x2,y2)]
[DRAW:screenN:poly(x1,y1;x2,y2;...)]
[DRAW:screenN:text(x,y,文本)]
[STEP:n:目标描述:rect(...)]                带做的一步
[POINT:none]                              明确不指
```

规则：

- 坐标为**该屏截图图片的像素坐标**（模型看到的图），由 `annotations::to_global()` 换算：`global = display.origin + px_picture × (display.width / shot.width_px)`。`display.scale` 只描述物理像素与逻辑点，**不能**用于模型图（模型图长边被缩到 1280）。解析必须同时拿到 `DisplayInfo` 与 `DisplayShot` 像素尺寸，缺失时拒绝换算。
- 越界坐标裁剪到该屏范围内；`screenN` 不存在 → 回退鼠标屏并记 `annotation.fallback_screen`。
- 标签长度裁剪到 40 字符；控制字符剥离。
- 解析后指纹（`plan_id`）用于前端幂等渲染。

## 07.1 带做的步数上限

`[STEP:...]` 一次最多 15 步；超出部分由解析层截断（与 TR-14、SDD §04.11 一致）。

## 08 理由与取舍

取舍：接受"可能被模型输出无关文本干扰"的风险，用严格正则 + 单测覆盖；放弃 JSON 的强约束以换取端点兼容与流式体验。

## 09 后果与剩余风险

中性变化：职责与接口按本决定重新分配，团队/Agent 的工作方式随之调整；既有习惯做法需要迁移。

正面：一个看图模型 + 标签即可指；换模型几乎无成本；测试可穷举语法。

负面：标签污染（模型把标签念出来）→ 提示词要求"不要朗读标签"，并在 TTS 前剥离注解。

剩余风险：模型对冷门软件坐标不准（无法工程消除，只能提供"指错了"反馈入口）。

## 10 实施约束与落实确认

- `annotations::strip_tags()` 必须先于 TTS 与文本展示执行。
- 渲染层不得自行解析文本；只接受 `PointerPlan`。
- 落实确认：`tests/annotations_*.rs`（≥20 用例）、`tests/e2e_ask.rs` 断言坐标。

落实确认分两类：**符合决策**（实现是否遵守本决定的约束）与**达到预期**（遵守之后是否真的改善了当初关注的问题）。前者通过不证明后者成立；若仅前者成立，应重新评估本决定而不是宣布成功。

## 11 重审条件、可逆性、退出路径

重审：兼容端点普遍支持 JSON schema；或需要 3D/视频注解。

可逆：高（解析器可并存 JSON 路径）。退出：`annotations` 增加 `from_json()` 并切换 prompt。
