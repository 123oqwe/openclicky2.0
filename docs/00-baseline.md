## 3. 命名与术语校正

用户口头说的 "TDD" 在两处含义不同，本项目全程区分：

- **TDD（测试驱动开发）**：开发方法，红—绿—重构。
- **TDD 文档**：本文档链第 5 项，正式名称 **《测试设计与验收规格》**（`docs/04-test-design.md`，文件内自称 TDS）。

## 4. 权威来源约定（冲突时按此裁决）

| 信息 | 权威来源 |
|---|---|
| 产品行为、功能编号、界面文案 | SRC-PRD |
| 技术承诺、契约、失败行为 | `docs/01-tech-prd.md` |
| 决策理由与代价 | `docs/adr/`（最新 Accepted 者） |
| 模块内部结构、算法、字段 | `docs/02-sdd.md` |
| 测试预期与证据 | `docs/04-test-design.md` |
| PR 是否合并 | GitHub 仓库实际状态 |
| 功能是否验收 | `docs/06-acceptance.md` 中绑定到具体 commit 的 G2/G3 结论 |
| Agent 的工作总结 | **不能**作为以上任何一项的替代证据 |

冲突处理：产品行为冲突 → 以 SRC-PRD 为准并开 ADR；技术冲突 → 按**适用范围与生效条件**判断哪份 ADR 有效（见 `docs/adr/README.md`），tech-prd 只保留当前有效结论；同范围冲突且无替代关系 → 新增 ADR 裁决；两者都无法裁决 → 记录到 `docs/02-sdd.md` 的"未决问题"并阻塞相关工作，不允许执行者自行挑一份最容易通过的文档。

## 5. 与原始资料的一处主动偏离

SRC-PRD 描述的是一款闭源商业产品，含付费套餐、团队后台、Chrome 扩展、3D 引擎等商业与规模要素。OpenClicky 2.0 的交付定义是**可日常使用的本地优先桌面产品**，因此：

- 保留并实现：说 / 教（指与画 + 带着做）/ 写 / 办（agent + 定时 + 建议）/ 记忆 / 用量 / 设置 / 引导 / 三平台部署。
- 明确不实现（并在 tech-prd §02 写为非目标）：支付结算与套餐扣费、团队后台、浏览器扩展、3D 模型渲染、应用商店/连接器市场。

此偏离不改变"可直接使用、不是 demo"的判据，见 `docs/01-tech-prd.md` §04 与 §18。
